# 25.10.2026 — VPN (xray) через туннель

## Итог
Рабочий VPN: клиент в Hiddify подключается к серверу X, трафик через туннель уходит на сервер Y и оттуда в интернет. Напрямую до Y из России достучаться не получалось — поэтому вход через X.

## Обозначения
- `X_IP` — IP сервера X (туннель) (16163)
- `Y_IP` — IP сервера Y (xray) (57395)
- `X_PORT` — порт на X, к которому подключаются клиенты
- `Y_PORT` — порт xray на Y

## Серверы

| Сервер | Что на нём |
|---|---|
| X | Туннель: `X_PORT` → `Y_IP:Y_PORT` (iptables). Ещё там свои сервисы (веб-сервер, Outline, xray) — туннель им не мешает |
| Y | `xtls/xray` на `Y_PORT`, `telemt/telemt-web` на 80/443 |

## Схема
```
Hiddify ──► X_IP:X_PORT ──iptables──► Y_IP:Y_PORT (xray) ──► интернет
```
Сайты видят IP сервера Y.

## Что делал

### Сервер Y: xray
`xtls/xray/settings.env`:
```bash
FAKE_DOMAIN=github.com
PORT=Y_PORT
```
```bash
cd ~/MTProto-proxy/xtls/xray
./start_proxy.sh
```
В ссылке из вывода заменил адрес и порт: `@Y_IP:Y_PORT` → `@X_IP:X_PORT`, остальное не трогал.

### Сервер X: туннель
```bash
sysctl -w net.ipv4.ip_forward=1

iptables -t nat -A PREROUTING -p tcp --dport X_PORT -j DNAT --to-destination Y_IP:Y_PORT
iptables -t nat -A POSTROUTING -p tcp -d Y_IP --dport Y_PORT -j MASQUERADE

# На сервере стоит Docker — без этих двух правил он режет пересылку
iptables -I DOCKER-USER -p tcp -d Y_IP --dport Y_PORT -j ACCEPT
iptables -I DOCKER-USER -p tcp -s Y_IP --sport Y_PORT -j ACCEPT
```

### Проверка
```bash
# на X: счётчики pkts растут при подключении
iptables -t nat -L PREROUTING -v -n | grep X_PORT
iptables -L DOCKER-USER -v -n | grep Y_IP
```
Hiddify подключается, 2ip.ru показывает IP сервера Y.
